### 2.2 计算口径

`GPA = Σ(课程绩点 × 课程学分) / Σ(计入课程学分)`。

以下是简化模式：同一目标评分体系、固定有效权重、历史记录不会被替换、剩余课程均计入且共同上下限为 L/M、目标含义为“至少达到 T”、按原值比较。其余情况见 2.4，不得直接套用：
- 最高最终 GPA：`(P + M × R) / (C + R)`。
- R > 0 时所需剩余平均绩点：`(T × (C + R) - P) / R`。
- 所需平均绩点 > M：理论上无法达到。
- 所需平均绩点 ≤ M：若所有剩余课程的最高值确实可同时取得，则至少存在全取最高值的理论方案；不保证实际表现，也不代表“恰好达到 T”或每门都能取到该平均绩点。
- 所需平均绩点 < 最低绩点 L：显示“剩余课程达到该规则最低绩点即可满足目标”，不显示负的目标要求。
- R = 0 且 C > 0：直接比较当前 GPA 与目标，不进行除以 R 的运算。
- C + R = 0：返回 `noData`。
- P/C/R/T/M/L 必须有限；C、R≥0，L≤M；C=0 时 P=0，C>0 时 L×C≤P≤M×C。目标超出量表范围返回 `invalidTarget`。计算前验证适用前提，前提不满足返回 `unsupportedPolicy`。

### 2.4 多学校适配设计与支持边界（新增，待团队批准）

基线冲突待决项：当前 Course 模型规定 positive credits，TC-ACA-002 明确拒绝零学分。下述零学分保留方案属于导入/跨学校扩展提案，获批准后须同步更新模型、需求与测试；未批准前仍执行 J-T06。分层/等权等汇总也不替代 FR-ACA-005 的学分加权基线。

**审核结论：原稿的加权公式可以复用，但仅靠换算表不能覆盖不同学校。当前交付是可扩展的规则设计，不是已实现的全学校计算器。** 同一学校不同入学年份、专业和用途也可能不同；学校名称不能作为唯一配置键。

建议将“原始成绩记录 → 政策处理 → 计算 → 展示”分开，并保留原始数据。首版维持学分加权 GPA 基线；新增规则属于待评审扩展，不能无声扩大 BASE-06 的实现承诺。

| 配置部分 | 必须明确的内容 |
| --- | --- |
| 身份与适用范围 | policyId、version、学校、学历/项目、适用入学年或生效区间、用途、官方来源、审核状态。计算结果绑定版本，政策更新不得静默覆盖历史结果 |
| 成绩转换 | 百分制分段表、等级映射、直接绩点、受控公式策略；允许输入域/精度、上下限及边界。映射可以多对一，不可假定能够反向求唯一成绩 |
| 课程选择 | 学期/累计/指定课程集、必修/选修/辅修、转入学分、退课、未出分、合格制及挂科的处理；同一批数据可产生不同用途的结果 |
| 重修与补考 | 独立 attemptId、课程等价组、次数/日期、首次/最新/最高/全部计入、补考封顶、替换归属学期、并列选择规则；顺序也应写入政策 |
| 汇总方法 | 首版 creditWeighted；扩展可有等权、显式权重、分组内加权后再按年级权重汇总。分层汇总不能简单给每课学分乘同一年级系数 |
| 精度规则 | 原始成绩、单课绩点、组内结果、最终结果、显示值各自的精度及舍入/截断规则；明确目标比较口径 |
| 输出解释 | 状态、原值/政策计算值/显示值、计入与排除的修读记录及原因、有效权重、政策标识、计算步骤；分层计算须保留各组汇总，不强造全局学分分母 |

最低数据建议：`courseId, attemptId, termId, credits, gradingStatus, gradeValue, gradeType, sourceScaleId`；重修适用时补 `equivalenceGroupId, attemptType, attemptDate`。分组规则需要 `yearLevel/courseCategory` 等字段；政策引用由计算请求或课程配置提供。所有名称与公共模型负责人对齐。

处理顺序由政策明确，至少包含：基础结构校验 → 范围筛选 → 状态判断 → 成绩转换及补考处理 → 重修记录选择 → 有效权重计算 → 汇总及政策舍入 → 展示。选择“最高”时按政策定义的比较量，不能对等级字符串排序。未评分的空成绩是合法状态，已评分却缺成绩是错误；未计入课程应留下排除理由。

同一目标政策可接收不同输入形式，例如百分制与等级制经各自已确认映射转为同一目标量表。真正不兼容的量表返回 `incompatibleScale`；不能按“除最高值再乘 4”自动转换。合办项目可以分别输出两个政策结果，不能默认混算。

建议错误状态：`invalidInput`、`missingPolicy`、`invalidPolicy`、`incompatibleScale`、`unsupportedPolicy`。规则未获确认与计算输入为空也要分开。公式采用受控策略和参数，不执行用户输入的任意代码。

**能力范围与验收：**
- 可配置范围：分段/等级/直接绩点转换、普通学分加权、明确的计入策略和重修策略；需实际实现及测试后才能声明支持。
- 需独立策略：非线性转换、分层年级汇总、特殊补考封顶或学分替代等。只配置最高分不能解决。
- 暂不承诺：所有学校预置、自动保证官方政策最新、完整学位等级/毕业资格判定。若规则依赖学位论文门槛、最低通过学分、等级分布或人工裁量，不能仅用 GPA 推断。
- 每新增一套真实学校政策，须有适用人群与官方来源、完整参数、正常/临界/重修/空数据样例及人工核对，评审后才标为 supported；缺项保持待确认。学校后续修改政策需新版本并重跑该政策案例。

#### 目标判断的扩展

固定分母的普通加权情况下，允许每门剩余课不同的可达上限 `M_i`：
`maxFinal = (P + Σ(w_i × M_i)) / (C + Σw_i)`。
这里 w_i 是 GPA 有效权重，不能用“毕业还差的学分”替代。分层汇总要按原政策重算每一组。若重修替换历史成绩，P 和 C 不再固定；若成绩影响课程是否计入，分母也可能变化。此时从完整课程快照调用专门策略，不能继续套用简化公式；未支持返回 `unsupportedPolicy`。

只有上限可同时取得且不存在其他约束时，最高值 ≥ 目标才可判理论可达。若只是一个乐观上界，低于目标可判不可达，高于目标只能返回 `unknown`，不能当作已找到方案。数值可行不等于满足毕业/学位条件。

## 3. K：时间计算建议规则

本节案例以以下“待确认建议规则”为前提。团队更改规则时，同步修改对应预期结果。

1. 占用区间用半开区间 `[start, end)`，必须 start < end。09:00–10:00 与 10:00–11:00 不冲突。
2. 时间必须带完整日期；跨午夜应明确使用次日日期。不能把同一天的 23:00–01:00 自动修成跨天。
3. 示例统一使用 Asia/Shanghai（UTC+8）；算法比较统一时间轴上的时刻。没有时区约定的输入应拒绝或在接口入口明确转换，不按设备默认值猜测。
4. 课程重复、教学周、取消和例外日期由日历模块先展开成具体 occurrence，再交给算法。是否支持其他地区时区与夏令时，由 BASE-05 确认。
5. 只有已安排且占用时间的记录参与冲突检测。仅有截止时间的未排程任务不形成占用区间。
6. 求空闲时段时，先裁剪到查询窗口，合并重叠或相接的占用区间，再求补集。仅接触窗口边界的记录不占窗口时间。
7. 建议首版采用整分钟精度，明确拒绝非整分钟输入；不得偷偷四舍五入。最小时段长度比较使用 ≥。
8. 排程允许恰好在截止时刻结束；所有分段必须在允许窗口内、不与占用时间重叠、总时长符合任务要求。
9. 排程输出是待确认建议，不自动覆盖现有安排。当前策略找不到解时返回 `noPlanFound`；只有必要条件已被证明不满足时才能称为 `infeasible`。

| 空闲时间查询 | 查询 start/end、占用区间列表、可选最小长度 | 按开始时间升序排列的、不重叠的空闲区间；无结果返回空列表 |

### 3.3 首版排程策略建议与限制

建议先按截止时间排序，同截止时间按稳定 taskId 排序；按时间顺序寻找可用段。拆分时需要避免留下小于最小段长的尾段，例如 50 分钟任务、最小段长 20 分钟可拆为 30+20，不能机械分成 40+10。

这一策略只作为待评审实现起点，不保证所有有解的多任务输入都能排出。若找不到结果但没有证明无解，返回 noPlanFound，并允许用户调整约束。不要把简单贪心算法的失败说成“任务一定排不下”。


### 3.4 补充校验与时间案例

允许窗口先取并集，再与最早开始/截止范围求交，扣除已有占用及本次已排任务；输出分段也必须彼此不重叠。输入分钟数与最小段长均为正整数；可拆分任务的每一段（含末段）都受最小段长限制。taskId 必须唯一。不可拆分任务不使用拆分最小段长。多任务输出要标注 complete/partial，以及每个未安排任务的原因；启发式失败不升级为已证明无解。

同一实例 ID 重复报错，不同实例 ID 即使时间相同，也应检测冲突；空闲查询计算并集不会重复扣时。排序须稳定（开始、结束、ID），便于回归比较。以下仍是测试设计。
