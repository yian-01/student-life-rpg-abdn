## Windows启动与录像

在本followup工作区的 `frontend/` 执行 `flutter run -d windows`，使用正式 `lib/main.dart`。或在候选构建后运行 `build/windows/x64/runner/Release/student_life_rpg.exe`，保留整个Release目录。不要使用旧PR程序／临时Web入口。

建议分三段录像：

1. `windows-SC01-SC09.mp4`：录制版本、启动正式应用进入日程；点工具栏“管理课程、作业与考试”建立学期和课程，经课程菜单“作业与考试”新建考试／作业。返回日程选同一天，增加事件和任务，五来源共存。点各行打开详情；把考试移至次日再返回，旧日消失；切到新日删除，取消后保留、确认后消失。作业同样改日／取消／删除，确认截止分区与时段分开。
2. `windows-boundaries-SC03-SC13.mp4`：真实任务／事件／考试各建23:30到次日00:10以及23:00到00:00，查看两天；检查09:00–10:00与10:00–11:00无冲突，改09:59有冲突；加入课程／考试混合重叠并完成任务，冲突计数同步变化。切跨月／跨年／2028-02-29／今天；清任务计划但保留截止；非法起止和取消保留原数据。拖小桌面窗口、Windows大字体，检查长文案和表单按钮。桌面检查不计Android软键盘实测。
3. `windows-recovery-SC10-SC14.mp4`：分别Task单坏、Campus单坏、双坏；恢复先取消再确认，无备份恢复失败也不清空健康数据。每种来源CRUD后点刷新日程，**完全关闭应用进程**再启动，检查编辑结果／删除无副本。录制任务保存／删除重复点击及切后台返回。

截图可保存 `windows-five-sources.png`、`windows-cross-midnight.png`、`windows-independent-errors.png`、`windows-cold-reopen.png`。请用人工操作生成的真实截图，不用Widget渲染代替。

## 故障检查数据保护

只在验收专用系统账户／已完整备份的合成验收数据上操作。应用数据通常在当前用户 `%APPDATA%` 下的应用支持目录；搜索 `campus.json`／`tasks.json` 确认目录，不直接使用源码目录。完整关闭程序后复制**整个数据目录**到安全位置，并记录原位置。备份不是让测试程序静默恢复。

要测试坏文件：保留原文件副本和 `.bak`，只把验收文件内容改成 `{bad`，冷启动。分别仅Task、仅Campus、同时两者；健康来源应显示。点击对应恢复，取消不变，确认后从有效备份恢复且保留`.corrupt`。无备份用独立验收数据目录测试，恢复失败提示可见。不要删真实个人记录来模拟故障。

已缓存后的外部文件变化识别是#30的独立存储验收点，本轮日程不声称已经修复。保存失败的真实系统权限注入由熟悉文件权限的验收负责人操作；自动测试已注入写失败，原生没操作则写未执行。
