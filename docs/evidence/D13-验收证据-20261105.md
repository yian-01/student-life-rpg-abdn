## 修复后的行为（对照 D1 要求）

| 要求 | 实现 | 状态 |
| --- | --- | --- |
| 普通 `list`/`getById` 不写主文件 | `_load` 只读：主文件损坏直接抛 `FormatException`，不再读 `.bak`、不再归档、不再写回 | 通过 |
| 不恢复旧数据 | 损坏主文件不会自动用 `.bak` 复活旧记录 | 通过 |
| 向 UI 传可识别失败 | 仓库抛 `FormatException`；日程页显示“日程加载失败，请重试。”+ 重试按钮（`day_schedule_page_test.dart` 已覆盖） | 通过 |
| 主文件缺失但有备份不能当首次运行 | 抛 `FormatException('主文件缺失但备份存在，需要显式恢复后才能读取')` | 通过 |
| 显式恢复只在用户确认后执行 | `TaskScheduleHost._recover` 先弹确认框，“取消”直接 return，不调用仓库 | 通过（代码审查） |
| 先完整验证备份 | `_restoreFromBackupDocument` 先 `_decodeTasks(backupRaw)`，失败不归档、不写盘 | 通过 |
| 归档损坏原件 | 归档为 `<tasks.json>.corrupt`，重名递增 `.corrupt.1`、`.corrupt.2`… | 通过 |
| 失败保留原件及有效备份 | 归档/写盘失败时 `.bak` 不被覆盖；写盘失败时内存保持调用前状态，可重试 | 通过 |
| 不提前提交内存 | 仅写盘成功后赋值 `_tasks` | 通过 |
| 取消不写盘 | 确认框返回 false 时不进入恢复流程 | 通过（代码审查） |
| 写入队列失败后仍可继续 | 队列尾任务吞掉错误（`onError: (_) {}`），后续请求可继续 | 通过 |

## 12 个必测场景的证据

| # | 场景 | 用例 / 证据 | 文件操作前后断言 | 结果 |
| --- | --- | --- | --- | --- |
| 1 | 单坏 Task | `主文件损坏时普通读取只报错，显式恢复后才写盘` | 读取前：主文件=损坏内容、`.bak`=有效；读取后：两者不变、无 `.corrupt` | 通过 |
| 2 | 单坏 Campus | `corruption rejects writes until explicit recovery and retains damaged original`（campus_persistence_test） | 拒绝写入、原件保留，显式恢复后可读 | 通过 |
| 3 | 双坏（Task+Campus 同时损坏） | 无专门组合用例 | — | 未测 |
| 4 | 缺主有备份 | `主文件丢失且备份存在时不得当作首次运行，显式恢复后恢复旧数据`；Campus 侧 `missing main with valid backup requires recovery, not empty initialization` | 读取后主文件仍不存在、`.bak` 不变；恢复后主文件=备份内容 | 通过 |
| 5 | 无主无备份（首次安装） | `首次无文件时 list 返回空列表` | 不创建主文件，返回空列表 | 通过 |
| 6 | 无备份（坏主无备份） | `主文件损坏且无备份时抛 FormatException 且不写盘` | 原件不变、无 `.corrupt`、无新增文件 | 通过 |
| 7 | 坏备份 | `非空但非法的备份被拒绝，显式恢复也不覆盖原件`；Campus 侧 `bad backup leaves damaged main intact and does not reset data` | 恢复抛 `FormatException`，主文件与 `.bak` 字节不变 | 通过 |
| 8 | 恢复取消 | 确认框逻辑：`confirmed != true` 直接 return（`task_schedule_host.dart`） | 未调用仓库，无写盘 | 未测（无 UI 自动化用例，仅代码审查） |
| 9 | 恢复中写失败 | `主文件损坏时普通读取不写盘，恢复失败后仍可重试且不丢失有效数据`（用同名目录阻塞临时文件） | 失败后主文件/`.bak` 至少一份有效、`.corrupt`=损坏原件；解除阻塞后重试成功 | 通过 |
| 10 | 归档存在（重复损坏） | `repeated corruption preserves both original documents`（file_store_fault_test） | `.corrupt` 与 `.corrupt.1` 分别保存两次损坏内容 | 通过 |
| 11 | 有效空 records | `有效 records=[] 时 list 返回空列表` | 不触发恢复、不写盘 | 通过 |
| 12 | 首次安装冷启动 | 同 #5；Campus 侧新建实例读到空数据 | 首次读取不产生 `.bak`/`.corrupt` | 通过 |

补充：`备份含已删除任务时冷启动不回滚，显式恢复才恢复旧数据`——`.bak` 中含已删除记录 b 时，普通读取只报错、不复活 b；显式恢复后记录回到 `[a, b, c]`，`.corrupt` 保存损坏主文件。通过。
